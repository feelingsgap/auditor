정답: ① (1번)

해설:
Slow HTTP Header, Slow HTTP POST, HTTP GET Flooding은 웹 애플리케이션 대상 DoS 유형에 대한 올바른 설명이다. 반면 일반적으로 알려진 공격 명칭은 동적 HTTP Request Flooding이며, 서버에 동적 페이지 생성 요청을 반복해 자원을 소모시킨다. 이를 '동적 HTTP Reply 공격'이라 하고 응답 메시지를 요구한다고 설명한 ①은 부적절하다.

각 보기 분석:
① '동적 HTTP Reply 공격'은 표준적으로 설명되는 공격 명칭과 행위가 맞지 않는다. 동적 페이지의 비싼 처리를 반복시키는 것은 동적 HTTP Request Flooding으로 보는 것이 타당하므로 부적절하다. 정답이다.
② Slow HTTP Header는 헤더의 끝을 보내지 않거나 매우 천천히 보내 서버가 요청 완성을 기다리며 연결 자원을 유지하게 한다.
③ Slow HTTP POST는 큰 Content-Length 등을 제시한 뒤 본문을 아주 느리게 보내 연결·스레드 자원을 오래 점유한다.
④ GET Flooding은 다량의 GET 요청을 보내 웹 서버와 백엔드의 처리 자원을 고갈시키는 응용 계층 DoS다.

시험 포인트:
Slow 공격은 반드시 큰 트래픽을 보내는 것이 아니라 적은 속도로 많은 연결을 오래 붙잡는 것이 핵심이다. Flooding은 요청량이나 처리 비용을 키우는 방식이다. Reply는 서버가 보내는 응답이고 Request는 클라이언트가 보내는 요청이라는 방향도 확인한다.

핵심 정리:
Slow HTTP 공격은 연결을 장시간 점유하고, HTTP Flooding은 다량의 요청으로 서버 자원을 소모시킨다.
