정답: ② (2번)

해설:
ㄱ은 질의 구조와 입력을 분리하므로 옳다. ㄴ도 저장 프로시저가 입력을 파라미터로 안전하게 처리하면 공격 가능성을 줄인다. ㄹ의 입력값 검증 역시 방어에 도움이 된다. 반면 ㄷ처럼 사용자 입력으로 Dynamic SQL 문자열을 조합하면 오히려 SQL Injection 위험이 커진다.

각 보기 분석:
ㄱ. Parameterized Query — SQL 코드와 데이터가 별도로 전달되어 입력값이 따옴표나 연산자를 포함해도 명령 구조로 해석되지 않는다. 가장 기본적인 방어책이다.
ㄴ. Stored Procedure — 프로시저 내부에서도 입력을 매개변수로 바인딩하면 위험을 줄인다. 다만 내부에서 문자열 연결로 동적 SQL을 만들면 다시 취약해질 수 있으므로 '파라미터로 처리'라는 조건이 중요하다.
ㄷ. Dynamic SQL — 외부 입력을 문자열에 직접 이어 붙이는 방식은 대표적인 발생 원인이다. 예방 방법이 아니다.
ㄹ. Input Validation — 형식·길이·범위·허용 문자를 검사해 비정상 입력을 줄이는 심층 방어책이다. 단, 이것만으로 파라미터 바인딩을 대체할 수는 없다.
①은 옳은 ㄹ을 누락한다. ②는 옳은 ㄱ·ㄴ·ㄹ만 포함한다. ③은 위험한 ㄷ을 포함하고 ㄴ·ㄹ을 누락한다. ④는 위험한 ㄷ까지 포함하므로 틀리다.

시험 포인트:
옳은 ㄱ, ㄴ, ㄹ의 조합은 ②다. Stored Procedure라는 이름만으로 안전한 것이 아니라 구현 방식이 안전해야 하며, 입력 검증만 믿고 SQL 문자열 연결을 허용해서도 안 된다.

핵심 정리:
SQL Injection 방어의 핵심은 Parameterized Query, 안전한 파라미터 처리, 허용 목록 기반 입력 검증이다.
