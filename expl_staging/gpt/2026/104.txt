정답: ① (1번)

해설:
A는 객체 식별자를 조작해 다른 사용자의 객체에 접근하는 Broken Object Level Authorization이다. B는 토큰·세션·API Key의 검증이나 관리가 미흡해 인증을 우회하는 Broken Authentication이다. 따라서 A-ㄱ, B-ㄴ이다.

각 보기 분석:
ㄱ. Broken Object Level Authorization — `/users/123/orders/7`처럼 객체 ID를 바꾸었을 때 서버가 현재 사용자의 소유권·권한을 매 요청마다 검사하지 않으면 다른 객체에 접근할 수 있다. A와 일치한다.
ㄴ. Broken Authentication — 약한 토큰 검증, 세션 관리 실패, 만료·서명 확인 누락 등으로 다른 사용자의 인증 상태를 가장하거나 우회하는 문제다. B와 일치한다.
ㄷ. Unrestricted Resource Consumption — 요청 횟수, 처리량, 메모리, 비용 등에 제한이 없어 자원이 고갈되는 문제로 A·B와 다르다.
ㄹ. Security Misconfiguration — 기본 계정, 불필요한 기능, 과도한 오류 노출 등 잘못된 보안 설정을 포괄한다.
①은 A와 B를 정확히 연결한다. ②는 인증과 객체 인가를 서로 뒤바꿨다. ③의 자원 소비 취약점은 B의 인증 실패와 무관하다. ④의 보안 설정 오류 역시 A의 객체별 권한검사 실패를 직접 설명하지 못한다.

시험 포인트:
①만 A-ㄱ, B-ㄴ으로 정확하다. 인증은 '누구인가'를 확인하고 인가는 '그 사용자가 이 객체·기능을 할 수 있는가'를 확인한다. 로그인에 성공했다는 이유로 객체 인가 검사를 생략하면 BOLA가 된다.

핵심 정리:
BOLA는 요청한 객체에 대한 권한 검증 실패이고, Broken Authentication은 사용자 인증 절차나 인증정보 관리의 실패다.
