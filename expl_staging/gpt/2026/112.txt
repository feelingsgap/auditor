정답: ① (1번)

해설:
저장소에 노출된 API 키는 이미 탈취되었다고 가정해야 한다. 즉시 키를 폐기해 사용을 차단하고 새 키를 발급해야 하며, 이후 저장소 이력 제거, 로그 점검, 비밀관리 시스템 적용 등을 수행한다.

각 보기 분석:
① 노출된 키를 폐기하고 새 키를 발급하면 공격자가 기존 값을 이용하는 경로를 즉시 끊을 수 있다. 가장 먼저 할 조치다.
② 저장소 접근 제한은 추가 노출을 줄이는 보완책이지만 이미 복제되었을 수 있는 키를 무효화하지 못한다.
③ 자동 만료 시점까지 공격에 악용될 수 있고, 모든 키가 자동 만료되는 것도 아니므로 부적절하다.
④ 저장소의 키 문자열을 나중에 암호화해도 이미 유출된 원본 키의 효력은 남는다. 폐기 없이 해결되지 않는다.

시험 포인트:
먼저 키를 revoke·rotate하고 관련 서비스가 새 키를 쓰게 한다. 다음으로 API 사용 로그에서 악용 여부와 영향 범위를 조사하고, Git 이력과 캐시의 노출값을 정리한다. 이후 환경변수만이 아니라 전용 비밀관리 시스템, 단기 자격증명, 최소 권한, 저장소 비밀 탐지를 적용한다. '삭제'와 '암호화'는 이미 유출된 자격증명의 폐기를 대신하지 못한다.

핵심 정리:
비밀정보 노출 사고의 첫 조치는 노출된 자격증명의 즉시 폐기와 교체다.
