정답: ③ (3번)

해설:
단층(Single-level) 페이지 테이블의 전체 크기를 계산하는 문항이다. 페이지 테이블은 가상 주소 공간의 모든 페이지마다 엔트리 하나를 가지므로, 전체 크기는 (총 페이지 수) × (엔트리 크기)로 구한다.

주어진 조건:
가상 주소 공간 = 4GB = 2^32 B
페이지 크기 = 4KB = 2^12 B
페이지 테이블 엔트리(PTE) 크기 = 4B = 2^2 B

계산 과정:
1단계 — 총 페이지 수 = 가상 주소 공간 / 페이지 크기
  = 2^32 / 2^12 = 2^20 = 1,048,576개 (약 100만 개)
2단계 — 페이지 테이블 크기 = 총 페이지 수 × 엔트리 크기
  = 2^20 × 2^2 = 2^22 B
3단계 — 단위 환산: 2^22 B = 4 × 2^20 B = 4MB

지수만으로 정리하면 32 - 12 + 2 = 22, 즉 2^22 = 4MB이다.

각 보기 분석:
① 4KB — 페이지 하나의 크기이지 페이지 테이블 전체 크기가 아니다. 값을 그대로 옮겨 쓴 오답.
② 1MB — 총 페이지 수(2^20 = 1M)만 계산하고 엔트리 크기 4B를 곱하지 않은 오답이다. 가장 빠지기 쉬운 함정이다.
③ 4MB — 2^20개 엔트리 × 4B = 2^22 B = 4MB. 정답.
④ 16MB — 엔트리 크기를 16B로 보거나 4를 한 번 더 곱한 오답이다.

핵심 정리:
단층 페이지 테이블 크기 = (가상 주소 공간 / 페이지 크기) × PTE 크기. 로그(지수)로 계산하면 실수가 줄어든다.
32비트 주소 + 4KB 페이지 + 4B PTE 조합은 프로세스당 4MB라는 고전적인 결과다. 프로세스가 100개면 페이지 테이블만 400MB가 필요해 현실성이 없으며, 이것이 다단계(multi-level) 페이지 테이블, 역페이지 테이블(Inverted Page Table), 해시 페이지 테이블이 도입된 이유다.
2단계 페이지 테이블에서는 실제 사용하는 영역의 하위 테이블만 메모리에 두면 되므로 메모리 사용량이 크게 줄지만, 주소 변환에 메모리 접근이 한 번 더 필요해 TLB(Translation Lookaside Buffer)의 중요성이 커진다.
32비트 가상 주소에서 페이지 크기가 4KB이면 오프셋은 12비트, 페이지 번호는 20비트로 나뉜다. 페이지 크기가 커지면 페이지 테이블은 작아지지만 내부 단편화가 늘어나는 트레이드오프가 있다.
