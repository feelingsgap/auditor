정답: ① (1번)

해설:
클라우드 API 키가 코드 저장소에 노출되었을 때의 즉각적 대응을 묻는 문항이다. 노출된 자격증명은 이미 유효성을 상실한 것으로 간주해야 하며, 최우선 조치는 해당 키를 즉시 폐기(revoke)하고 새 키를 발급하여 교체하는 것이다.

각 보기 분석:
① 노출된 키를 폐기하고 새 키를 발급한다 — 맞음. 커밋 이력이나 포크, 캐시, 크롤러 등을 통해 이미 유출되었을 가능성이 있으므로 키를 무효화해야 악용을 차단할 수 있다. 폐기가 완료되어야 이후의 이력 정리, 영향 분석, 재발 방지가 의미를 가진다. 정답.
② 코드 저장소 접근 권한을 제한한다 — 재발 방지와 확산 억제에는 도움이 되지만, 이미 노출된 키 자체는 여전히 유효하므로 공격자가 클라우드 자원을 계속 사용할 수 있다. 즉각적 대응으로는 불충분하다.
③ API 키는 일정 기간 후 자동 만료되므로 조치가 불필요하다 — 틀림. 만료 시점까지 공격자가 자원을 탈취하거나 과금을 유발할 수 있고, 다수의 클라우드 API 키는 자동 만료되지 않는다. 위험을 방치하는 잘못된 판단이다.
④ 키를 암호화한다 — 저장소에 남은 값을 암호화해도 이미 평문으로 노출된 원본 키는 무효화되지 않는다. 암호화는 사전 예방(비밀관리 시스템 사용) 수단이지 사고 후 즉각 대응이 아니다.

핵심 정리:
자격증명 유출 대응 순서: 즉시 폐기·재발급 → 해당 키의 사용 이력과 이상 접근 조사 → 저장소 이력에서 비밀값 제거(git filter-repo 등) → 비밀관리 시스템 도입과 시크릿 스캐닝 자동화.
노출된 비밀은 "회수"가 불가능하다. 삭제 커밋만으로는 이력·포크·캐시에 남아 있으므로 반드시 폐기해야 한다.
예방 대책: 코드에 비밀값 하드코딩 금지, .gitignore와 pre-commit 스캐너, 환경변수·Secret Manager 사용, 키 최소권한 부여와 주기적 순환.
