정답: ② (2번)

해설:
시스템 카탈로그(데이터 사전, data dictionary)의 개념과 성질을 묻는 문항으로, 옳지 않은 설명을 고른다. 시스템 카탈로그는 데이터베이스에 저장된 모든 객체(테이블, 뷰, 인덱스, 제약조건, 사용자, 권한 등)의 정의와 명세, 즉 메타데이터를 담고 있는 시스템 테이블들의 집합이다.

각 보기 분석:
① SQL 질의가 실행될 때 질의처리기는 반드시 시스템 카탈로그를 참조해야 한다 — 파싱 단계에서 테이블·컬럼의 존재 여부와 타입, 권한을 확인하고, 최적화 단계에서 인덱스 정보와 통계 정보를 얻으려면 카탈로그 참조가 필수다. 옳은 설명이다.
② SYSTEM_LOG는 SQL 표준으로 정의된 가상 스키마로 테이블·컬럼·제약조건 등 메타데이터를 표준화된 방법으로 조회하게 한다 — SQL 표준이 정의한 메타데이터 조회용 가상 스키마의 이름은 INFORMATION_SCHEMA다. SYSTEM_LOG라는 표준 스키마는 존재하지 않으며, log는 메타데이터가 아니라 회복(recovery)을 위한 트랜잭션 기록이다. 틀린 설명이므로 정답.
③ DDL이 실행될 때마다 DBMS가 자동으로 카탈로그 테이블의 행을 삽입·삭제·수정한다 — CREATE/ALTER/DROP의 결과가 카탈로그에 자동 반영되는 것이 정상 동작이다. 옳은 설명이다.
④ 모든 데이터 객체의 정의와 명세에 관한 정보인 메타데이터를 유지·관리한다 — 시스템 카탈로그의 정의 그 자체다. 옳은 설명이다.

핵심 정리:
시스템 카탈로그의 핵심 성질: 사용자는 SELECT로 조회만 가능하고 INSERT/UPDATE/DELETE로 직접 갱신할 수 없다. 갱신은 DDL 수행 시 DBMS가 자동으로 처리한다.
표준 메타데이터 조회 경로는 INFORMATION_SCHEMA이며, 제품별 구현으로 Oracle의 데이터 사전 뷰(USER_TABLES, ALL_TABLES, DBA_TABLES), SQL Server의 시스템 뷰 등이 있다.
카탈로그에 저장되는 통계 정보(투플 수, 블록 수, 컬럼별 값 분포)는 비용 기반 최적화기(CBO)가 실행 계획을 선택하는 근거가 되므로 주기적 통계 갱신이 성능 관리의 기본이다.
메타데이터(카탈로그)와 로그(회복용 변경 이력)는 목적과 관리 주체가 다른 별개 구조라는 점이 이 문제의 함정 포인트다.
