정답: ② (2번)

해설:
금융기관 배포 보안 통제 요건으로 직무 분리, 비밀번호 인지 없는 야간 자동배포, 장애 시 한시적 권한 상향과 사후 감사 추적이 제시되었다. 시간·승인 상태·장애 여부 같은 동적 상황(컨텍스트)에 따라 권한을 판단해야 하므로 속성 기반 접근 제어(ABAC)가 적합하고, 서비스 계정은 비밀관리 시스템에서 단기 자격증명을 동적으로 발급받아야 한다.

각 보기 분석:
① RBAC 적용 + 서비스 계정 고정 비밀번호 공유 — 역할 분리는 가능하지만 RBAC는 정적인 역할 기반이라 시간대나 장애 상황 같은 조건부 권한 판단이 어렵다. 특히 고정 비밀번호를 공유하면 "운영자가 비밀번호를 인지하지 않아야 한다"는 요건을 정면으로 위배하고 책임추적성도 훼손된다.
② ABAC 적용 + 비밀관리 시스템의 단기 자격증명 — 주체·자원·행위·환경 속성(시각, 승인 상태, 장애 여부)을 정책으로 평가하여 야간 자동배포와 장애 시 한시적 권한 상향(Just-In-Time 권한)을 구현할 수 있고, Vault류 비밀관리 시스템이 동적 단기 자격증명을 발급하므로 운영자는 비밀번호를 알 필요가 없다. 모든 발급·사용 이력이 남아 사후 감사 추적성도 확보된다. 정답.
③ DAC 적용 + 긴급 시 운영자 직접 권한 추가 — 소유자 재량으로 권한이 확산되고 운영자가 스스로 권한을 부여하므로 직무 분리와 승인 통제가 무너진다. 금융권 통제 요건에 부적합하다.
④ MAC 적용 + 관리자 수동 일괄 승인 — 보안등급 기반의 경직된 모델이라 시간·장애 조건 반영이 어렵고, 수동 일괄 승인은 야간 무인 자동배포 요건과 배치된다.

핵심 정리:
RBAC는 역할이라는 정적 집합으로 권한을 부여하고, ABAC는 주체·객체·행위·환경 속성을 조합한 정책으로 실행 시점에 권한을 판단한다. 시간대, 위치, 승인 상태, 장애 여부 같은 조건이 등장하면 ABAC다.
비밀번호 인지 없는 자동화 요건은 비밀관리 시스템(Secret Manager/Vault)의 동적 단기 자격증명과 자동 순환으로 해결한다.
장애 시 한시적 권한 상향은 JIT 권한 부여와 사후 감사(권한 상향 이력, 작업 로그, 자동 회수)를 함께 설계해야 한다.
