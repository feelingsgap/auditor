정답: ② (2번)

해설:
Nested Loop Join(NL 조인), Sort-Merge Join, Hash Join의 동작 방식과 적용 조건을 구분하는 문항이다. 보기 가와 나는 두 조인 방식의 설명이 서로 뒤바뀌어 있다.

각 보기 분석:
가. Sort-Merge Join이 선행 테이블 행별로 후행 테이블을 반복 탐색하며 인덱스가 없으면 Table Full Scan이 반복된다 — 이는 Nested Loop Join의 설명이다. Sort-Merge Join은 양쪽을 정렬한 뒤 한 번씩 스캔하며 병합하므로 반복 탐색이 없다. 틀렸다.
나. Nested Loop Join이 인덱스 없이도, 부등호 조인에도 쓸 수 있고 이미 정렬되어 있으면 정렬 단계를 생략한다 — 정렬 단계 생략은 Sort-Merge Join의 특성이며 NL 조인에는 애초에 정렬 단계가 없다. 설명 대상이 뒤바뀌어 틀렸다.
다. Hash Join은 동등 조인에만 사용 가능하며, 대량 데이터 처리 시 일반적으로 NL 조인이나 Sort-Merge Join보다 효율적이다 — 해시 값이 같아야 같은 버킷에 들어가므로 등가 조건(=)에서만 쓸 수 있고, 대량 데이터를 인덱스 없이 처리할 때 가장 효율적인 방식으로 알려져 있다. 옳다.
라. Hash Join은 해시 테이블을 메모리에 생성하며 메모리에 적재할 수 없을 만큼 커지면 일부를 임시영역(디스크)에 저장한다 — 메모리가 부족하면 파티션 단위로 디스크에 쓰는 Grace Hash Join 방식으로 처리한다. 옳다.

따라서 옳은 것은 다와 라이므로 ② (다), (라)가 정답이다.
① (가), (나) — 두 보기의 설명 대상이 서로 뒤바뀌어 모두 틀렸다.
② (다), (라) — Hash Join에 대한 정확한 설명 둘만 묶었다. 정답.
③ (가), (다) — 가가 NL 조인 설명이라 틀렸다.
④ (나), (다), (라) — 나가 틀렸다.

핵심 정리:
Nested Loop Join: 선행 테이블 행마다 후행 테이블을 반복 탐색. 소량 데이터와 후행 테이블 인덱스가 있을 때 유리하며 부등호 조인도 가능하다.
Sort-Merge Join: 양쪽을 조인 키로 정렬 후 병합. 인덱스 없이도 가능하고 이미 정렬되어 있으면 정렬 단계를 생략한다.
Hash Join: 작은 쪽으로 해시 테이블을 만들고 큰 쪽을 탐침(probe). 등가 조인 전용이며 대량 데이터에 가장 유리하다.
반복 탐색은 NL, 정렬 후 병합은 Sort-Merge, 등가 조인 한정은 Hash라는 키워드로 뒤바꾸기 함정을 피한다.
