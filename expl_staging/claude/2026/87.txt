정답: ① (1번)

해설:
라운드 로빈(Round Robin) 스케줄링에서 시간 할당량(Time Quantum)의 크기가 극단으로 갈 때의 동작을 묻는 문항이다. RR은 준비 큐를 FIFO로 관리하면서 각 프로세스에 정해진 시간 할당량만큼만 CPU를 주고, 시간이 다 되면 선점(preemption)하여 큐 맨 뒤로 보낸다.

각 보기 분석:
① FCFS(First Come First Served) — 시간 할당량이 무한히 커지면 어떤 프로세스도 할당량을 소진하기 전에 스스로 종료되므로 선점이 한 번도 일어나지 않는다. 결국 준비 큐에 도착한 순서대로 각 프로세스를 완료할 때까지 실행하게 되어 FCFS와 동일하게 동작한다. 정답.
② HRRN(Highest Response Ratio Next) — 대기 시간과 실행 시간의 비율((대기시간 + 서비스시간) / 서비스시간)로 우선순위를 계산하는 비선점 알고리즘이다. RR은 실행 시간을 고려하지 않으므로 시간 할당량을 아무리 키워도 HRRN이 되지 않는다. 오답.
③ SJF(Shortest Job First) — 실행 시간이 짧은 작업을 먼저 처리하는 비선점 알고리즘이다. RR은 실행 시간 정보를 사용하지 않고 도착 순서대로 순환하므로 SJF와 무관하다. 오답.
④ SRTF(Shortest Remaining Time First) — SJF의 선점형 버전으로, 남은 실행 시간이 더 짧은 프로세스가 도착하면 즉시 선점한다. RR의 시간 할당량을 키우면 오히려 선점이 사라지는 방향이므로 정반대다. 오답.

핵심 정리:
시간 할당량 → 무한대: RR은 FCFS와 동일해진다(선점 소멸, 문맥 교환 없음, 응답 시간 악화).
시간 할당량 → 0에 근접: 프로세서 공유(Processor Sharing)에 가까워져 모든 프로세스가 동시에 1/n 속도로 실행되는 것처럼 보이지만, 문맥 교환 오버헤드가 폭증해 실제 처리량은 급락한다.
따라서 적정 시간 할당량은 "대부분의 프로세스가 한 번의 CPU 버스트를 끝낼 수 있으면서 문맥 교환 비용이 과도하지 않은 수준"으로 잡으며, 일반적으로 CPU 버스트의 80% 정도가 할당량 내에 끝나도록 설정한다.
알고리즘 분류 — 비선점: FCFS, SJF, HRRN, 우선순위(비선점) / 선점: RR, SRTF, 다단계 큐, 다단계 피드백 큐.
함정 포인트는 RR을 "짧은 작업 우대" 알고리즘으로 오해하는 것이다. RR은 도착 순서만 보며, 짧은 작업이 빨리 끝나는 것은 결과일 뿐 판단 기준이 아니다.
