정답: ④ (4번)

해설:
TDD(Test-Driven Development)는 켄트 벡이 제시한 XP의 실천법으로, 구현 코드보다 테스트 코드를 먼저 작성하는 개발 방식이다. 절차는 Red - Green - Refactor 사이클로 요약된다.

TDD 사이클:
Red 단계: 아직 구현되지 않은 기능에 대한 테스트를 먼저 작성한다. 실행하면 당연히 실패한다.
Green 단계: 그 테스트를 통과시킬 수 있는 최소한의 코드를 작성한다.
Refactor 단계: 테스트가 통과하는 상태를 유지하면서 중복 제거와 구조 개선을 수행한다.
이 사이클을 짧게 반복하며 기능을 늘려간다.

각 보기 분석:
① 설계 - 코드 작성 - 테스트 수행 — 전통적인 폭포수형 순서로, 테스트가 마지막에 오므로 TDD가 아니다.
② 코드 작성 - 테스트 수행 - 리팩토링 — 코드를 먼저 작성한 뒤 테스트하므로 Test-First 원칙에 어긋난다. 테스트가 개발을 주도하지 않는다.
③ 테스트 작성 - 리팩토링 - 코드 작성 — 구현 코드가 없는데 리팩토링부터 한다는 것은 성립하지 않는다. 리팩토링은 통과하는 코드가 있어야 가능하다.
④ 테스트 작성 - 코드 작성 - 리팩토링 — Red, Green, Refactor 순서와 정확히 일치한다. 정답.

핵심 정리:
TDD의 순서는 실패하는 테스트 작성(Red) → 통과하는 최소 코드 작성(Green) → 리팩토링(Refactor)이며 이 순서를 뒤집으면 TDD가 아니다.
리팩토링은 항상 테스트가 통과하는 상태에서 수행되어야 하며, 테스트가 안전망 역할을 한다.
TDD의 효과는 회귀 결함 조기 발견, 테스트 가능한(낮은 결합도) 설계 유도, 살아 있는 명세 확보이다.
BDD, ATDD도 Test-First 계열이지만 각각 행위 명세와 인수 조건을 기준으로 한다는 점에서 구분된다.
