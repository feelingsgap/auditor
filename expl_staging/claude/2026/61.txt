정답: ③ (3번)

해설:
NOT EXISTS를 사용한 상관 서브질의의 결과를 도출하는 문항이다. NOT EXISTS는 서브질의 결과가 공집합일 때 참이 되므로, R의 각 행 중에서 "S에 A가 같고 C가 'c3'인 행이 하나도 없는" 행만 선택된다.

주어진 인스턴스:
R(A, B) = (1, a), (2, b), (3, c), (5, x).
S(A, C) = (1, c1), (2, c2), (3, c2), (1, c5), (5, c4), (2, c1), (1, c3), (3, c4), (5, c3), (3, c5).

S에서 C = 'c3'인 행만 추리면 (1, c3)과 (5, c3)이며, 해당 A 값 집합은 {1, 5}다.

R의 각 행 판정:
A=1, B=a: S에 (1, c3)이 존재하므로 서브질의가 공집합이 아니다. NOT EXISTS 거짓 → 제외.
A=2, B=b: A=2이면서 C='c3'인 행이 없다. NOT EXISTS 참 → 선택.
A=3, B=c: A=3인 S 행은 (3, c2), (3, c4), (3, c5)뿐이고 c3이 없다. NOT EXISTS 참 → 선택.
A=5, B=x: S에 (5, c3)이 존재한다. NOT EXISTS 거짓 → 제외.
결과 B = {b, c}.

각 보기 분석:
① B = {a, b} — a는 A=1이며 (1, c3)이 존재하므로 NOT EXISTS 조건에서 탈락한다.
② B = {a, x} — a(A=1)와 x(A=5) 모두 c3을 가진 행이 있어 오히려 EXISTS 조건(부정하지 않은 질의)의 결과다.
③ B = {b, c} — A=2와 A=3에는 C='c3'인 대응 행이 없으므로 정확한 결과다. 정답.
④ B = {c, x} — c는 맞지만 x(A=5)는 (5, c3)이 존재하므로 포함될 수 없다.

핵심 정리:
EXISTS/NOT EXISTS는 서브질의가 행을 반환하는지 여부만 보므로 SELECT 목록의 내용은 무의미하다(SELECT * 또는 SELECT 1 모두 동일).
NOT EXISTS는 "조건을 만족하는 짝이 하나도 없는" 안티조인(anti-join) 의미로, NOT IN과 달리 서브질의에 NULL이 있어도 예상대로 동작한다는 장점이 있다.
상관 서브질의 내부의 A = R.A처럼 바깥 별칭을 참조하는 조건이 있으면 R의 행마다 서브질의가 재평가된다는 점을 기억한다.
