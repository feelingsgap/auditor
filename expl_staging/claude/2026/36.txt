정답: ④ (4번)

해설:
소프트웨어 형상관리(SCM, Software Configuration Management)의 4대 활동을 적용 시기 순으로 나열하는 문항이다. 표준적인 순서는 형상 식별 → 형상 통제(변경관리) → 형상 상태 보고(기록) → 형상 감사이다.

각 항목이 어느 활동인지 판별:
가. 변경에 대한 반영이 정확히 이루어졌는지 평가한다 → 형상 감사(Configuration Audit)
나. 형상 항목에 대한 상태를 기록하고 보고한다 → 형상 상태 보고(Status Accounting)
다. 변경 요청 발생 시 평가와 변경 승인 등을 수행한다 → 형상 통제(Configuration Control), CCB의 역할
라. 기준에 따라 형상 항목을 선정하고 항목 간 관계를 정의한다 → 형상 식별(Configuration Identification)

따라서 라(식별) → 다(통제) → 나(상태 보고) → 가(감사) 순이다.

각 보기 분석:
① 라, 나, 다, 가 — 식별 다음에 상태 보고가 오는데, 보고할 변경 이력이 생기려면 변경 통제가 먼저 수행되어야 하므로 순서가 어긋난다.
② 라, 다, 가, 나 — 감사와 상태 보고의 순서가 뒤바뀌었다. 상태를 기록·보고한 결과를 근거로 감사가 수행된다.
③ 다, 라, 나, 가 — 형상 항목을 식별하지도 않은 상태에서 변경 통제를 먼저 할 수 없으므로 시작부터 틀렸다.
④ 라, 다, 나, 가 — 식별 → 통제 → 상태 보고 → 감사의 표준 순서와 일치한다. 정답.

핵심 정리:
형상관리 4대 활동은 식별, 통제, 상태 보고(기록), 감사이며 여기에 형상관리 계획 수립이 앞에 붙기도 한다.
형상 식별에서 형상 항목(CI)과 베이스라인을 정하고, 형상 통제는 CCB가 변경 요청을 심의·승인하며, 상태 보고는 변경 이력과 현재 버전을 기록하고, 형상 감사는 변경이 요구대로 반영되었는지 검증한다.
감사는 항상 마지막 검증 단계라는 점을 기준으로 순서 문제를 푼다.
